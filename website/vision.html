Where ToolTwin fits in
the robot economy.

ToolTwin is the visible tip of a bigger idea: a synthetic-data & robot-training platform that plugs into Omnipresent Robotics' operational loop. This page explains the technology landscape, where MeetKai operates, and what's built so far.

The operational loop

Omnipresent's loop runs from supply chain to deployment and back. MeetKai plugs into two stations — Training and Data — the part that turns robots into capable workers.

The technology landscape

Four terms, one stack.

Modern robot-learning is built from four layers that sit on top of each other.

Foundation

NVIDIA Omniverse

NVIDIA's platform for physically-accurate 3D worlds, based on the OpenUSD scene format — the "engine and file standard" for industrial digital twins.

Where our 3D artists' assets & scenes live.
Engine

NVIDIA Isaac

NVIDIA's robotics stack on Omniverse. Isaac Sim simulates robots and generates synthetic training data; Isaac Lab trains the AI policies.

Turns our 3D data into robot skills.
Open layer

Genie Sim

AgiBot's open-source simulation platform, built on Isaac Sim and tuned for humanoid manipulation — LLM scene generation, large datasets, validated sim2real for the G1/G2.

On-brand: Todd buys AgiBot robots.
The method

sim2real

Train a robot's brain entirely in simulation and deploy on a real robot — bridged by domain randomization (varying lighting, textures, physics, positions).

Why synthetic data is valuable.
Omniverse / OpenUSD → Isaac Sim → Genie Sim → sim2real policy

MeetKai feeds the bottom (3D assets) and operates the middle (simulation + training).

The product

The cake, and the cherry.

Two layers — one is the recurring business, the other is the on-ramp that brings people to it.

The cake — the core business

Synthetic Data & Training Platform

A dedicated, GPU-backed service that generates synthetic 3D data, trains robot policies in simulation, and validates sim2real transfer to AgiBot hardware.

  • Authored by our 3D team, expanded with domain randomization
  • Web layer for humans — configure, launch, monitor, download a policy
  • API for software & AI agents to drive data + training programmatically
The cherry — the hook

ToolTwin

Describe a tool in plain language → an AI writes parametric CAD → you get a printable STL + a web/sim GLB → tune it → send it straight into training.

  • A creative, memorable front-door in a competitive market
  • Create the tool here, train your robot here, deploy on AgiBot robots
  • Draws developers & customers into Todd's ecosystem
Status today

What's actually built.

A working web prototype with a real AI + CAD backend, and a faithful mock-up of the heavy training engine — the right order to validate the funnel before investing in the full GPU stack.

Partly real

Tool Foundry

Describe → Tune → Export, with a live 3D viewport. A real AI service (OpenAI) returns a parametric spec and even invents new parameters from the prompt; a real CadQuery service returns STL + GLB + print stats.

Placeholder: the CAD geometry is simple for now — real recipes come next.
Realistic mock-up

Training Studio

Robot → Task → Train: pick an AgiBot G1/G2, attach your tool, set domain randomization & policy, launch, and watch a live dashboard (episodes, success rate, sim2real gap).

This is the human web layer; it doesn't yet run real simulations.
Live

Backend services

Two cloud services deployed: the OpenAI-driven AI bot and the CadQuery build service. The frontend degrades gracefully to offline mode if they're unavailable.

Built on Node, Python/FastAPI, and CadQuery.
Where this goes

Next steps.

  1. 01
    Confirm the wedge — Training + Data as MeetKai's lane in Omnipresent's loop.
  2. 02
    Stand up a minimal real backend — one GPU server running a single task end-to-end (scene → data → train → sim2real policy) behind the existing Training Studio UI and a small API.
  3. 03
    Productionize ToolTwin geometry — replace placeholder CadQuery with genuinely useful, well-modeled, oriented tool recipes.
  4. 04
    Package the data offering — asset libraries and randomized scene generators as the sellable "synthetic data" product.
  5. 05
    Go API-first — publish the programmatic interface so partners and AI agents can consume data + training without the UI.
